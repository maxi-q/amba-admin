## Реализация и границы API

- Одна общая страница `src/pages/(list_integration)/ord/profile.tsx` для реального приложения и стенда; прежние отдельные create/card/FIO/phone компоненты объединены.
- Существующие app-level hooks POST/PUT сохранены. POST: inn/name/phone/juridicalType. PUT: только изменённые name/phone.
- Сохранены проверка контрольной суммы ИНН по типу лица, полное ФИО, RU-телефон и E164. Единое поле ФИО не обрезает имена длиннее трёх слов.
- API не содержит иностранного контрагента, номера электронного средства платежа, страны, адреса и признака фиксации в актах. `syncedAt` не используется как признак блокировки.
- Пользователь явно выбрал интерактивное демо неподдерживаемых полей только на мок-стенде. Обычное приложение отключает переключатель и объясняет ограничение. ИНН/тип существующего профиля не редактируются (их нет в PUT).
- Preview provider подключается только из `src/dev/preview-app.main.tsx`; дополнительно защищён `import.meta.env.DEV`. Демо-реквизиты — локальное состояние формы, не DTO и не localStorage. Создание иностранного профиля локальное и не отправляет фиктивный POST с ИНН. Создание резидента и изменение ФИО/телефона используют те же hooks/контракты с мок-ответами.
- Страны в демо — небольшой демонстрационный список, не справочник бэкенда.
- Для реальной иностранной формы нужны соответствующие поля/валидация в POST/PUT/GET; для запрета после актов — явный признак/набор редактируемых полей и серверное ограничение. Новые API-поля вручную в generated не добавлялись.

## Как открыть и проверить

`http://127.0.0.1:5173/task-status-log-preview.html?path=/rooms/preview-room/ord/profile`

Параметр `ord-profile`: `new` — создание, `resident` — сохранённый резидент, `locked` — блокировка после актов, `production` — тот же мок API без unsupported-fields provider. Без параметра — иностранный профиль из Figma; изменение поля показывает вариант с предупреждением.

Проверено в браузере: точная геометрия карточки358×504/кнопки93×40; создание, редактирование, локальное сохранение реквизитов, ошибки ФИО/телефона/ИНН, неизменяемость типа после создания, модалка по заблокированному полю и доступность ФИО, disabled foreign в production-сценарии. Проверки: `node scripts/ord-profile.test.mjs`, build, ESLint изменённых файлов. Production bundle не содержит тестовые ФИО/реквизиты/сценарий фиксации в актах.
