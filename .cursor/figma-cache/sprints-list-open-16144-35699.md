## Сделано в коде

- Список: плоские строки (название, чип статуса, даты), шапка «Спринт» + «+ Добавить».
- Открытый спринт: `/rooms/:slug/sprints/:sprintId` — заголовок, edit/add actions, segmented tabs «Задания» / «Рейтинг», отдельный поиск и правая панель `260px`.
- Plus открывает существующую форму создания задания с уже выбранным текущим спринтом.
- Правая панель использует реальные reward rules и `reward.iconUrl`, отдельно показывает рейтинг и ручной отбор.
- Лидерборд использует реальные `entry.rewards`, XP и границу зоны вознаграждений.
- Search визуально и интерактивно совпадает на mock-наборе; при смене строки сбрасывается первая страница.
- Authless visual-flow доступен в `task-status-log-preview.html`.
- Редактирование: `/rooms/:slug/sprints/:sprintId/edit` (бывшая форма настроек).
- Legacy-вкладки SprintsHeader только на settings / info / leaderboard комнаты.

## Gap vs API / макет

1. Черновики `SprintDraft` — на беке есть сервис/таблица, **HTTP endpoints в Swagger нет** → UI «Сохранить черновик» ещё заглушка.
2. Розовый бейдж «5» у названия / в сайдбаре — нет источника в API.
3. ~~Описание спринта~~ — подключено (`description`).
4. ~~Квесты / sprintId~~ — при запуске и в открытом спринте фильтр по `sprintId`; `restrictions` отдельно от description.
5. Лидерборд API — только активный спринт комнаты; для других спринтов — заглушка.
6. Backend leaderboard не принимает `search`, поэтому production-поиск пока фильтрует только загруженную страницу. Для глобального поиска нужен query-параметр на беке.
7. DTO итоговой награды не содержит contribution breakdown, нужный точному tooltip «Фиксировано / Плавающий процент».
8. Reward detail отдаёт фото, но reward DTO не содержит описание — модалку из `16492:71183` нельзя заполнить полностью без расширения контракта.
9. Иконки календаря/карандаша — lucide с геометрией `20/16px`, stroke `1.5`; удаление не добавлено без отдельного подтверждения поведения.
10. Выбор спринта при создании задания вне wizard — простой Select (без отдельного макета).
