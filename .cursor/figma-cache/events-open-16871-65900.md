- Without a configured promo reward the event has two tabs: contest uses `Задания / Рейтинг`; everyone uses `Участники / Задания`.
- With an active promo rule the conditional middle tab appears: contest uses `Задания / Промокод / Рейтинг`; everyone uses `Участники / Промокод / Задания`.
- Event shell uses a `680px` main column and a `260px` information rail after the application sidebar.
- Header title is `20/32`; edit/add controls are `28×28`; filters and list rows are `48px` high.
- Tasks show platform, frozen state, execution counters, and pause/play action.
- Task detail uses `Выполнение / Информация`, a search field on the execution tab, `149px` three-step progress, and a task metadata rail.
- Contest participant profile is centered at `700px` without the event rail; everyone profile uses a `648px` card column plus the `260px` event rail.

## Backend / implementation

- Backend `main` commit `c9a31a5` adds `/api/events/{eventId}/tasks` and event-task submission endpoints.
- OpenAPI was regenerated through Orval. `scripts/prepare-openapi.mjs` normalizes the inherited `page` and `size` query fields that Swagger exposes as `Object` even though the backend DTO validates integers.
- `OpenEventPage.tsx` renders real event tasks, the matching rating/participant view, and the conditional promo journal for the configured reward mode.
- `EventParticipantPage.tsx` now renders real task activity and the contest/everyone layouts from the paired profile frames.
- `EventTaskPage.tsx` implements the task execution and information shell using event-task submissions.
- Everyone profiles in the awarding state separate delivery confirmation for task rewards and promo-code rewards.
