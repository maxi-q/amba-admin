## Что уже поддерживает API

- `byRank`: `rankFrom`, `rankTo`, массив `{ rewardId, amount }`.
- `byPoints`: пропорциональный пул в `amount`, фильтры `rankTo` и/или `minPoints`.
- Несколько наград в одном правиле.
- CRUD правил после создания спринта.
- Каталог наград комнаты: `name`, `iconUrl`.
- Проверка принадлежности награды комнате.
- Целочисленное пропорциональное распределение методом наибольших остатков.

## Можно решить на фронте

1. Stepper, переключение трёх вкладок, «Назад» и disabled-state «Продолжить».
2. UI «Рейтинга»: диапазоны мест, выбор нескольких наград, редактирование и удаление.
3. UI «Ручного выбора»: каталог, `− / +`, удаление и пустое состояние.
4. UI «Пропорционально»: сумма и зона до N места.
5. Проверка `from <= to`, положительных количеств, обязательных полей и отсутствие дублей наград.
6. Расчёт конфигурационного «Итогового пула» для `byRank`: количество наград × число мест.
7. Скрыть `minPoints`: для `byPoints` достаточно передавать `rankTo`.

## Требуется backend / продуктовое решение

1. **Черновик спринта.** Reward-rules требуют `sprintId`, но шаг 2 идёт до публикации. Нужен `draft | published` или отдельный draft endpoint.
2. **Ручное распределение.** В API есть только автоматические `byRank` и `byPoints`. Нет типа `manual`, пула ручных наград и назначения наград конкретным участникам.
3. **Тип награды.** Каталог хранит только `name` и `iconUrl`; нельзя гарантировать условие «только денежные».
4. **Денежное значение и валюта.** Нет структурированных `value/currency`; поле «Общая сумма в рублях» нельзя надёжно связать с `rewardId`.
5. **Пересечения диапазонов.** Сейчас правила могут пересекаться и суммируются. Нужно зафиксировать: запрещать пересечение или явно разрешать.
6. **Точный preview пула.** При ничьих competition ranking фактическое число получателей может отличаться от числа мест; отдельного preview endpoint нет.
7. **Описание спринта.** Поле шага 1 всё ещё отсутствует в Sprint API.

## Отложенные backend-задачи

- Жизненный цикл спринта: `draft | published` (или отдельный draft endpoint).
- Ручной режим и его модель: пул спринта и/или назначения участникам.
- Опциональный preview endpoint для итогового пула/распределения.
- `description` в Sprint DTO/schema, если поле должно сохраняться.
