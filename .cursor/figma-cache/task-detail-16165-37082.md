## Implementation

- `CreativeTaskDetailLayout.tsx`: exact shell, sprint back-flow, and shared right metadata rail that stays visible at the desktop Figma width despite the duplicated Tailwind utility order.
- `CreativeTaskDetailHeader.tsx`: live `Выполнение / Информация` filters row, URL-backed search on the execution route; other deep routes remain functional but are not shown in this Figma scope.
- `CreativeTaskDescriptionPage.tsx`: product description; combined task description/files/text templates/target links card; restrictions; criteria. The extra «Креатив ОРД» card was removed from this design scope.
- `TaskDetailSubmissionsList.tsx`: real submissions, ambassador avatar/name fallback, client-side name/ID search, progress states and status-log dialog.
- `StopCreativeTaskDialog.tsx`: shared Figma confirmation dialog for the sprint row and task detail.
- `OpenSprintQuestRow.tsx`: the task link and stop button are sibling controls, so the stop click no longer navigates to the task.
- `task-status-log-preview.html`: authless interactive mock for the complete sprint → task flow with exact Figma media/reward assets.

## Backend limits

- Ambassador DTO has `username` and optional `avatarUrl`, but no separate full name; production falls back to the generated `Avatar` initials when the image is absent.
- The submissions endpoint has no search parameter. The current UI search filters the loaded page; add backend search + regenerate Orval for cross-page search.
- `defaultMediaIds` has IDs, but the current app hook has no preview URL; production shows file placeholders, mock uses Figma thumbnails.
- There is no task paused/frozen field or endpoint. The confirmation opens, but deliberately does not map freeze to `isDeleted`: that field is documented as deletion and would hide/remove the task instead of preserving existing executions.
- To finish persistence, backend needs a separate `isFrozen` (or `status: active | frozen`) field in update/list/detail/ambassador DTOs and a server-side guard that rejects new submissions while allowing already started executions. Then regenerate Orval and connect the existing `useUpdateCreativeTask` hook.
