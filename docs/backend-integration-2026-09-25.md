Основание: Swagger и read-only исходники Ambassador backend `26e41d1`.
Бэкенд не изменялся; запросы на создание/модерацию/выдачу проверялись только на локальном мок-стенде.

## Подключено в основном приложении

- Спринты и события: `active → reviewing → awarding → completed`; получение статистики проверки, подтверждение досрочного завершения, фиксация итогов. Завершить выдачу нельзя, пока остались невыданные назначения.
- Рейтинг конкретного спринта (`sprintId`), серверный поиск и пагинация, разделение XP заданий/промокодов. Итоги берутся из серверного снимка, а не пересчитываются на фронте. Исторические соревнования без снимка не показывают выдуманные результаты.
- Ручное назначение наград одобренным участникам, изменение количества/снятие назначения, остаток пула и точность количества. Выдача/отмена выдачи, история; отмена выдачи завершённого соревнования возвращает его в awarding.
- Задания выбранного спринта загружаются с `sprintId`. После фиксации итогов модерация отключена и в списке выполнений, и в журнале задания.
- `byPoints.rankFrom` поддерживается в редакторе, сохранении и локальном превью. Распределение остатка учитывает место; при нулевых XP у всех участников пул делится поровну.
- События доступны из основного меню. Создание/редактирование: настройки и черновик → участники и правила наград → XP за промокоды → публикация. Типы «Конкурс» и «Для каждого», правила byRank/byPoints/manual/each, явное обновление версий наград. Существующие обязательные параметры промокода сохранены.
- Участники события, поиск по результатам, профиль с назначениями и начислениями. Изменение состава не заменено отдельным списком мок-пользователей.
- Правило XP за каждые N успешных активаций: создание, новая версия при изменении, отключение, история, прогресс, начисления и пагинация. Старые начисления сохраняются.
- Отмена одного адресата приглашения через `DELETE /api/invitations/:id/targets/:targetId`, без удаления остальных адресатов.
- Сохранение правил промокода явное; выход с несохранёнными настройками события требует подтверждения. Ошибки не очищают введённые данные. Публикация ждёт обновления списка событий перед переходом на страницу результата.

## Что ещё зависит от бэкенда

- **Задания событий:** отсутствует поддерживаемая связь/CRUD. В мастере нет неработающего шага заданий; третий шаг настраивает существующий API промокодных XP.
- **Денежные бонусы за промокоды из макета:** новый promo-points API начисляет только XP, не деньги. Старые обязательные `rewardValue/rewardUnits` события не подменяют такую механику.
- **Дополнительные реквизиты ОРД:** остаются в ранее согласованном демо-режиме; новый контракт их не добавил.
- Файлы/загрузки отложены по договорённости; сотрудники/роли не включались в эту интеграцию и не запрашиваются у бэкендера.

Неблокирующее замечание к Swagger: сервис списка событий возвращает type/status/isDraft и даты жизненного цикла, но PickType DTO их не описывает. Ручные получатели вне рейтинга могут иметь `rank: null`, хотя Swagger описывает число. Эти подтверждённые исходниками расхождения учтены в `scripts/prepare-openapi.mjs`, после чего Orval перегенерирован. Generated-файлы вручную не редактировались. После исправления Swagger нормализацию можно убрать.
