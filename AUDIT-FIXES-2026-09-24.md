- HTML «Участники»: `/src/dev/prototypes/audit-fixes.html?screen=participants`
- HTML «ОРД»: `/src/dev/prototypes/audit-fixes.html?screen=ord`
- HTML «Журнал»: `/src/dev/prototypes/audit-fixes.html?screen=journal`

HTML — проверочный артефакт, не альтернативная реализация рабочего приложения и не production entry. Иллюстрация журнала в HTML — образец Figma, не поддельное вложение реального пользователя. В приложении выводится доступное содержимое API и явное ограничение для медиа. Исторические версии материалов не выдумываются.

- Браузер: массовое одобрение трёх заявок; ограничения удаления; карточка и модалка ОРД; материалы до публикации; неудачная модерация с сохранением комментария; успешная повторная отправка и новый статус.

## Что ещё не закрыто

Нельзя назвать весь продукт полностью соответствующим Figma: остаются backend-зависимые итоги, медиа и исторические ответы, персональная выдача наград, досрочное завершение проверки, новые события и промокодное начисление. Конкретные запросы — в `BACKEND-REQUESTS-2026-09-24.md`.

Ниже приоритет этой итерации: legacy-ошибки событий A20, ручной старый DTO промокодов A21, профиль исполнителя/раскрытие +N и остальные точки входа A22, сохранение аватарки компании из A19. Они не объявлены исправленными. Нужен отдельный проход; визуальные изменения также начинать с HTML.

Гарантия повторов ограничена полученными ответами сервера и текущей сессией формы. Потерянный ответ POST, перезагрузка и атомарное изменение уже активного спринта требуют поддержки бэка, а не дополнительных обещаний фронта.
